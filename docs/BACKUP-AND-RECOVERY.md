# Резервное копирование и восстановление

Снимок диска VPS **недостаточен** как единственная резервная копия.

## Что копировать

1. **Файлы сайтов** — `/home/<siteUser>/htdocs/` и связанные каталоги пользователя сайта.
2. **Базы данных** — дампы через CloudPanel / `clpctl` / `mysqldump` от имени с минимальными правами.
3. **Конфигурации**, необходимые для восстановления доступа: список доменов, DNS, правила firewall провайдера, версии PHP.
4. **Не** кладите приватные ключи и пароли в обычные журналы `logs/`.

## Куда копировать

Вне основного VPS: S3-совместимое хранилище, Wasabi, Spaces, SFTP, другой регион.  
CloudPanel поддерживает Remote Backups — см. официальные Best Practices:

https://www.cloudpanel.io/docs/v2/guides/best-practices/security/

## Периодичность

- БД: чаще (зависит от интенсивности изменений).
- Файлы: ежедневно или по политике RPO.
- Тест восстановления: регулярно на **отдельной** среде.

## Проверка целостности

1. Сверьте размер и checksum архива после копирования.
2. Разверните копию на тестовом VPS.
3. Импортируйте БД, проверьте логин WP и ключевые страницы.
4. Зафиксируйте время восстановления (RTO).

## Восстановление после сбоя установки

Если установщик CloudPanel упал:

1. Сохраните журналы проекта.
2. Предпочтительный путь для продакшена малого бизнеса: **новый чистый Debian** + повтор этого комплекта.
3. Не пытайтесь «дочистить» полуустановленный стек без опыта — высок риск скрытых конфликтов.

## Восстановление сайта WordPress

1. Поднимите CloudPanel на чистом Debian.
2. Создайте сайт (или PHP site) с тем же доменом.
3. Восстановите файлы в home site user.
4. Восстановите БД.
5. Обновите `wp-config.php` (секреты вводите вручную, не из Git).
6. Выпустите TLS заново после DNS.
