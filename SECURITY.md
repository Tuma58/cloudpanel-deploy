# Безопасность проекта cloudpanel-deploy

## Принципы

1. Установка только на **чистый** поддерживаемый Debian VPS.
2. Только **официальный** установщик CloudPanel и контрольная сумма из официальной документации.
3. Никаких паролей, токенов и приватных ключей в Git.
4. Разрушительные действия только после явного `CONFIRM_INSTALL=YES`.
5. Конфликтующие службы **не удаляются** автоматически.
6. Откат после неудачной установки **не автоматизируется** (может быть опасен).

## Секреты

Не храните в репозитории:

- пароли CloudPanel / WordPress / БД;
- SSH private keys;
- API-токены провайдера;
- TLS private keys;
- заполненный `config/deploy.env` с боевыми данными.

`config/deploy.env` исключён через `.gitignore`. Права на журналы: каталог `750`, файлы `640`.

## Сеть

- Порт **8443** — только для IP администратора.
- Порты **22** — ограничить по возможности.
- **80/443** — публично для сайтов и Let's Encrypt.
- **3306** — не публиковать.

См. `config/firewall-requirements.md` и `docs/NETWORK.md`.

## Администратор CloudPanel

Создавайте пользователя **только через официальный UI** сразу после установки. Не используйте прямые SQL-запросы к внутренней БД панели.

## Отчёт об уязвимостях

При обнаружении проблемы в скриптах проекта: исправьте локально, обновите CHANGELOG, сверьте установщик с актуальной документацией CloudPanel.
